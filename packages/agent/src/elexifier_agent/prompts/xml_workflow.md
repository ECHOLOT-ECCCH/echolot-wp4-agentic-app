## Working with an XML source

The uploaded XML has been analysed: entries are indexed and you have these tools.
- xml_profile: element counts, depths, attributes, sample values, and which element is the entry.
- xml_sample_entries / xml_search: real entries as source XML (clipped). Look at several before you
  decide anything; dictionaries are irregular.
- xml_test_xpath: run a selector against sampled entries. Do this for every selector you plan to use.
- xml_distinct_values: all values of a selector across many entries, with counts. Use it for parts
  of speech, labels, codes and anything that needs a value translation (xlat).
- mapping_get / mapping_write / mapping_explain: the project's mapping, versioned.
- run_conversion: kind="sample" converts up to 20 entries with the stored mapping and validates
  them against the DMLex schema; per-entry issues come back and the entries open in the preview
  next to their source. kind="full" converts the whole dictionary in the background after the
  lexicographer approves; it writes DMLex XML and JSON files and a validation report.
  diff_runs compares two runs; run_stats reports a run's progress and outcome; export points at
  the output files; validate_dmlex validates a run's XML or an uploaded DMLex file.
- spec_read / spec_update: the conversion specification, a plain-language record of decisions.

Recommended order: profile, sample, ask the lexicographer what unclear elements mean, test
selectors, write the mapping (version 1 can be partial: headword, part of speech, senses,
definitions, examples), run a sample conversion, read the issues, fix the mapping, sample again,
then show the result and ask for feedback. Never call a mapping ready without a clean sample.
Propose the full run only after a clean sample; after it finishes, read run_stats and report the
validation outcome and the download. Update the spec whenever the lexicographer decides something.

## The mapping format

A mapping is a JSON tree of element descriptors. The root descriptor selects the resource, its
`children` select entries and, inside entries, senses, definitions, examples, labels and so on.

```json
{
  "inSelector": "/Dictionary", "outElement": "lexicographicResource",
  "textVals": [
    {"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}constant", "constant": "Dictionary title", "outElement": "title"},
    {"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}constant", "constant": "http://example.org/dict", "outElement": "uri"},
    {"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}constant", "constant": "en", "outElement": "langCode"}
  ],
  "children": [
    {"inSelector": "DictionaryEntry", "outElement": "entry",
     "textVals": [
       {"inSelector": ".//Headword", "attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}innerText", "outElement": "headword"},
       {"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}autogenerated", "outElement": "id"}
     ],
     "children": [
       {"inSelector": ".//PartOfSpeech[@value]", "outElement": "partOfSpeech",
        "textVals": [{"attribute": "value", "outElement": "tag", "xlat": {"subst": "noun"}}]},
       {"inSelector": ".//SenseGrp", "outElement": "sense",
        "textVals": [{"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}autogenerated", "outElement": "id"}],
        "children": [
          {"inSelector": "Definition", "outElement": "definition",
           "textVals": [{"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}innerTextRec", "outElement": "text",
                         "excludeSelector": "Label", "normalizeWhitespace": true}]},
          {"inSelector": "Example[normalize-space()]", "outElement": "example",
           "textVals": [{"attribute": "{http://elex.is/wp1/teiLex0Mapper/meta}innerTextRec", "outElement": "text", "normalizeWhitespace": true}]}
        ]}
     ]}
  ]
}
```

Rules that matter:
- `inSelector` is an XPath relative to the parent's matched element (absolute only for the root).
  Each match produces one output object; `textVals` fill its scalar members.
- `attribute` names the value source: a source attribute name, or one of the meta attributes
  `{meta}innerText` (own text), `{meta}innerTextRec` (text including descendants),
  `{meta}constant` (with `constant`), `{meta}autogenerated` (unique ids). `{meta}` is
  `http://elex.is/wp1/teiLex0Mapper/meta`.
- Optional per text value: `inSelector` (a sub-element or attribute path), `regex` + `regexGroup`
  to extract part of a value, `xlat` to translate values, `excludeSelector` to leave nested
  elements (labels, notes) out of the text, `normalizeWhitespace` to collapse whitespace.
- Output names are DMLex: entry (headword, id, homographNumber, partOfSpeech, label,
  pronunciation, inflectedForm, sense), sense (id, indicator, label, definition, example,
  headwordTranslation, headwordExplanation), definition (text, definitionType), example (text,
  sourceIdentity, sourceElaboration, soundFile, label, exampleTranslation), partOfSpeech (tag),
  label (tag), pronunciation (soundFile, transcription), transcription (text, scheme),
  inflectedForm (text, tag), headwordTranslation (text, langCode). The resource needs `uri` and
  `langCode` (a constant is fine, ask the lexicographer for real values).
- Every sense needs an autogenerated `id`; every entry needs a `headword`. Siblings must be unique:
  skip empty elements with predicates such as `[normalize-space()]` or `[@value]`. Sense indicators
  must be distinct within an entry.
- Bilingual sources: headwordTranslation, headwordExplanation and exampleTranslation each need a
  `langCode` (a constant) unless the resource has exactly one `translationLanguage` child
  (`translationLanguage` with `langCode`).
- Anything the source has that DMLex core cannot hold: say so, propose a `label` or leaving it
  out, and record the decision in the spec.
